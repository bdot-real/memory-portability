\begin{abstract}
Assistants built on large language models keep memory about their users, but each vendor stores
it in its own format, so switching engines resets what the assistant knows. Following Gruber's
translation approach, we store user memory against a shared ontology and translate it for each
engine with thin adapters. We contribute (i) a taxonomy of agent memory by portability;
(ii) \memcore, a small OWL extension of PROV-O and SKOS, published in a versioned registry that
generates the JSON Schema for extraction and the Model Context Protocol (MCP) tools for read-out; (iii) the portability
fidelity metric (\PFM); and (iv) an open-source prototype and benchmark of synthetic multi-session
personas. Across six cross-engine pairs of open-weight models, the gold store reaches a \PFM of
\res{pfm-oracle-large} on \res{tok-hist-large}k-token histories with
\res{tok-ratio-oracle-b-large}$\times$ fewer prompt tokens than the transcript
(\res{pfm-b-large}). Stores written by the 7--14B source engines reach only \res{pfm-a2-large}, but
a store written once by a stronger model reaches \res{pfm-a2x-opus-large} with the same small
readers, matching a frontier model that reads the whole transcript (\res{pfm-b-opus-reader-large})
with \res{tok-ratio-a2x-b-large}$\times$ fewer tokens. Structured memory also adds a failure mode:
an engine that over-applies an erasure request deletes true memories.
\keywords{Agent memory \and Portability \and Ontologies \and PROV-O \and MCP \and LLM evaluation}
\end{abstract}
